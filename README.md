# Auto Skip

Windows 10 x64 短视频过滤助手，支持抖音桌面客户端和 Chrome 中的抖音网页版。通过半透明浮窗管理本机作者／关键词／链接黑名单，辅助切换视频。

**当前桌面程序为 0.1.20 开发预览版，配套 Chrome 扩展版本为 0.1.13，最新发布日期为 2026-10-04。** 当前过滤流程完全在本机运行，无需 API Key。版本号、发布日期和作者邮箱（huangyangh2004@gmail.com）可在「设置 → 关于」中选中复制。

- 作者、关键词和链接规则支持「或／与」组合，以及手动添加、编辑、启停、删除和快捷键撤销。
- 「监听」从快速手动划走中学习视频黑名单；「自动」按启用规则跳过，两项可独立或同时运行。
- 桌面端按窗口句柄捕获画面和定向切换，支持播放器 OCR 排除区域及有效区域预览。
- 保存观看统计，支持导出、导入、重置，可选择按有效历史观看时长自动跳过，默认关闭。
- Chrome 扩展通过当前用户的 Native Messaging 连接，共用桌面程序的规则和设置。

已完成自动测试及部分客户端实机验证，完整一期验收仍在进行。真实 Chrome 扩展联调、多显示器和更多客户端版本等剩余验证见 [VALIDATION.md](VALIDATION.md)；[PLAN.md](PLAN.md) 含历史设计，当前功能以本说明为准。

## 使用

1. 保持发布文件夹完整，双击 `AutoSkip.exe`。不需要另装 Python。
2. 首次运行默认暂停、监听开启、自动关闭。打开抖音客户端，程序自动发现并绑定窗口。也可点浮窗的「绑定窗口」，再用鼠标点击抖音窗口确认。
3. Chrome 网页版按下文加载扩展并注册连接。
4. 回到抖音推荐视频页，在浮窗点击「开始」。
5. 勾选「监听」：客户端首次切换建立计时基准；之后两次有效切换动作间隔小于 5 秒，就保存划走前的快照并后台入库。阈值可修改。网页版则依据已观察到的播放时长和用户切换信息学习，需有可靠视频 ID 和播放计时。
6. 勾选「自动」：执行已启用规则，命中后跳过。可以同时勾选「监听」，一边自动过滤，一边从用户的快速手动切换中学习。网页版取得可靠播放结束信息时会切换下一条；客户端不持续读取播放进度，正常视频由用户切换，或使用可选的历史时长自动跳过。

「开始／暂停」是总开关，不改变监听和自动的勾选状态。两项都关闭时不自动学习或跳过。开关选择会保存；升级时保留旧版的选择，例如原来是自动模式，则迁移为自动开启、监听关闭。浮窗状态、提示和视频文字各有固定显示区域，长内容可悬停查看全文。点击「开始／暂停」右侧的「−」隐藏文字区域，点击「+」恢复显示；黑名单、绑定窗口等操作按钮始终保留，文字更新不改变浮窗高度。

**作者或文字识别有误时，点击解析文字左侧的重新解析图标**，从绑定客户端的当前画面重新识别一次。此次使用本地 RapidOCR 重新读取，完成后更新显示及本视频缓存；后续手动拉黑和当前观看区间的统计使用新信息，观看计时保留。解析期间按钮暂时禁用；作者未读出或画面不可用时显示提示，保留原文字，可再次尝试。暂停、窗口重绑或视频切换后，迟到的结果会被丢弃。按钮仅在桌面窗口已绑定且开始运行时可用，Chrome 网页版持续读取页面文字。

运行时不显示黄色截图边框。**按住「开始／暂停」左侧的区域图标**，显示当前播放器配置的有效播放区域绿色边框，内部透明，松开鼠标左键立即隐藏；暂停时也可以验证。边框使用已保存的排除区域，不遮挡播放器画面、不接收鼠标、不触发 OCR。隐藏浮窗、更改设置或重新绑定窗口时也会清除预览。Windows 10 22H2 使用 `PrintWindow` 按句柄获取画面；支持关闭系统边框的较新系统继续使用 Windows Graphics Capture。

浮窗「拉黑作者」会将当前作者加入本机规则并跳过，旁边下拉菜单可选择仅拉黑视频。需要撤销黑名单时，打开「黑名单」列表，选择对应规则后删除或停用。程序不操作抖音账号的拉黑、点赞或不感兴趣按钮。

从当前视频或划走前画面加入黑名单时，必须解析出作者名称；未识别到作者则放弃添加，即使已有视频或作者账号 ID 也不会入库。此要求适用于手动拉黑作者／视频及快速划走学习；手动拉黑失败时也不会因此切换视频。

作者账号 ID 可用时优先使用 ID；桌面端只有识别出的作者名时，按完整作者名建立或匹配规则，并清理 `@`、OCR 空格、发布时间和「主页」后缀。名称显示在黑名单的「作者」列。不会因标题或正文提到某人、作者名前缀相同而命中；已有两个不同的可靠账号 ID 时也不会仅因同名而匹配。按名称匹配本身无法区分同名账号。

如果系统 OCR 将已拉黑作者的名字读成近似字，程序只针对作者那一行调用另一 OCR 引擎复核；必须复核得到完整一致的名字才命中，不直接按模糊相似度跳过。旧版误存的 `dy:author:self`／`dy:author:me` 规则会按已有作者名修复，保留启用状态；这些“我的主页”链接不再作为视频作者 ID。

## 黑名单规则

点击「黑名单 → 手动添加」，填写作者、关键词、链接并选择过滤条件，也可从浮窗拉黑按钮的菜单选择「手动添加规则」。支持编辑、搜索、启用／停用和删除；手动添加的规则也可在黑名单列表中删除或停用。

- **或**：至少填写一项，作者、关键词、链接任一项匹配即命中；空白项不参与匹配。
- **与**：作者、关键词和链接三项都必须填写，解析到的三项也必须全部匹配；缺少任何一项均不命中。
- **作者**：按完整作者名称匹配，清理 `@`、OCR 空格与发布时间；不会因正文提及作者或名字前缀相同而命中。
- **关键词**：在视频标题及解析文字中做包含匹配，忽略大小写、全半角及空白差异。每条规则填写一个关键词或短语；多个独立关键词可分开建规则。
- **链接**：按完整链接匹配，支持播放器中的可见链接以及文字识别出的 URL。抖音视频链接按视频 ID 匹配，分享参数不影响同一视频的识别；其他链接保留路径和参数，不按地址前缀匹配，也不会主动打开链接。

例如作者「张三」、关键词「手机」、链接「https://www.douyin.com/video/123」：选择「或」时三者中任一项命中就跳过；选择「与」时三者必须同时命中。作者和链接留空、关键词填写「广告」并选择「或」，则只按该关键词过滤。

从当前视频或快速划走加入的视频黑名单会保留已解析的作者和标题，标题显示在「关键词」列，过滤条件显示「仅视频」，仍按视频身份精确匹配。编辑时默认保留此行为；选择「或」或「与」后可修改作者、关键词和链接，将其转为组合过滤规则。未取得标题时关键词留空。旧视频规则优先从同一视频的观看记录补回缺失信息；有旧标题时也会恢复到关键词列，无法恢复的作者不作推测。

旧作者和视频规则保留精确匹配和启停状态。旧截图学习的视频若没有真实链接，在链接列显示「已学习视频」，仍按作者和完整标题识别。旧类别记录保留在数据库中，但不再显示、不参与过滤，也不能新增。新版不调用类别云端判断，无需配置 API Key；旧的加密 Key 不会被删除。

## 自动过滤

勾选「自动」并点击开始，程序将解析当前视频的作者、标题／文字和可取得的链接，再执行已启用的规则；不同规则之间任一规则命中即跳过。

客户端以向下滚轮、下方向键、有效拖动及工具自己发送的跳过消息作为重新识别的触发。取得作者即缓存，包括没有完整标题的情况；切换后即使仍是同一位作者，也会重新识别。尚未取得作者时继续尝试，窗口暂停、重新绑定、最小化或画面丢失后恢复时也会重新读取。切换动画中的旧作者不会立刻锁定为下一条；自动切换未确认时仍保留超时停止保护。

## 播放器 OCR 排除区域

打开「设置 → 播放器区域」，选择当前使用的播放器类型。预置「抖音桌面版 Windows」，默认排除**下方 100 像素**，用于减少「下一章」「发一条友好的弹幕吧」等播放工具栏文字的干扰。可新增、重命名和删除播放器类型，每个类型独立保存多个排除区域；保存时选中的类型应用于当前绑定的桌面播放窗口。

点击「添加排除区域」，选择上方、下方、左侧或右侧并输入正整数像素跨度。跨度从绑定窗口的原始截图边缘向内计算，在 OCR 缩放之前生效。例如下方 100 排除整条底部 100 像素；同时配置左侧 30，则左边 30 像素也不参与识别。同方向的多个区域取最大跨度，不重复累加。点击行号选择区域后可删除；删除全部区域恢复整窗识别。

填写「窗口进程」（例如 `douyin.exe`），**按住「验证有效区域」**即可使用当前页面尚未保存的排除配置查找对应窗口、截取有效画面，并在原窗口对应位置显示截图和绿色边框。松开按钮立即隐藏；切换设置页、切换播放器类型或关闭设置也会清除预览，迟到的截图不会重新显示。验证异步截取画面，绿色预览不接收鼠标、不激活播放器、不运行 OCR，也不保存配置或截图。

验证优先使用进程匹配的已绑定窗口，否则查找该进程唯一的可见且未最小化窗口。未找到、找到多个候选、窗口关闭或移动／缩放期间截图失败时，会在按钮下方提示；抖音多窗口可先通过浮窗绑定需要验证的窗口。旧配置没有进程字段时按 `douyin.exe` 处理。「窗口进程」用于区域验证，常规播放绑定仍支持现有抖音 Windows 客户端。

配置同时作用于自动识别、手动拉黑时的识别、作者 OCR 复核和快速划走快照。手动读取的界面控件文字也会限制在保留区域内，避免工具栏文字重新进入结果。若窗口缩小后排除区域覆盖整个画面，停止本次 OCR 并提示减小跨度。保存设置后清除旧识别缓存；窗口缩放后按固定像素重新计算区域。

当前区域以整个绑定窗口为边界，不自动查找窗口内部的视频矩形。播放器类型是可切换的 OCR 配置，窗口绑定仍支持现有的抖音 Windows 客户端。Chrome 网页版从网页读取视频文字，不使用桌面截图排除配置。

## 观看统计与历史时长自动跳过

开始运行并开启监听或自动后，点击浮窗「观看统计」查看已完成视频的观看次数、总观看时长、平均观看时长，以及有效观看的相应统计。有效观看须**严格高于**设置中的快速跳过阈值：阈值为 5 秒时，5 秒不属于有效观看，低于 5 秒的手动快速跳过仍可学习黑名单。调整阈值后，已有观看记录会按新阈值重新筛选。

统计表固定显示「跳过」类别：所有已完成、观看时长严格小于当前阈值的记录归入该行，分别统计次数、总时长和平均时长。跳过记录仍计入全部观看，但不参与有效视频的关键词分类和历史时长预测；等于阈值的记录仅计入全部观看。修改阈值后自动重新归类。

在「观看统计」底部点击「导出记录」保存 JSON 备份，包含原始观看记录、时间、作者、标题、视频身份、来源和旧版计时标识，可恢复统计及历史时长预测。点击「导入记录」选择备份，与本机记录合并；重复导入同一备份不会增加次数，备份中真实重复的观看次数仍会保留。导入前校验全部记录，失败时不写入；统计按本机当前阈值重新计算。点击「重置统计」并确认后清空全部观看记录（包括旧版记录），同时放弃当前未完成区间及历史时长预测；黑名单、设置和最近操作保留。重置后从下一次切换重新建立计时起点；清空的记录可通过备份重新导入。

分类和历史时长分析仅使用有效观看。根据解析出的标题／话题关键词在本机归入数码科技、美食、旅行风景等类别；未识别到通用类别的话题标签作为独立类别，没有关键词的记录为「未分类」。视频可属于多个类别，每个类别分别计算平均时长，类别次数不能相加。

勾选「自动」后，可勾选「按历史时长自动跳过」，默认关闭。每条新视频优先使用同一视频的有效历史平均观看时长；没有同一视频记录时，使用匹配类别的有效平均时长，多类别匹配优先采用样本最多的类别。没有可靠视频身份或有效匹配历史时继续观看。相同视频跨来源使用视频 ID 或作者与完整标题识别；已知不同视频 ID 不会仅因标题相同被当作同一视频。

例如同一视频有效历史平均为 10 秒，本次累计播放达到 10 秒时请求下一条。当前观看记录不参与自身预测，目标时长在本条开始时确定；工具跳过不学习黑名单，命中黑名单仍优先跳过。关闭历史时长自动跳过后停止计时跳过，普通自动黑名单过滤继续工作。

统计以两次视频切换之间的墙钟时间间隔为准，不依赖播放进度、进度文字是否可见或播放状态。一次切换同时结束上一条、开始下一条，直到下一次切换才保存这条的时长。因此启动时已经在播放的第一条视频不保存，退出时未发生下一次切换的最后一条视频也不保存。**首次切换只建立起点，第二次切换才产生第一条完整统计记录。** 当前仍在播放的视频不会提前加入均值或自身历史预测。

桌面使用 Windows 原始切换输入事件的时间；工具自动跳过使用成功发送下一条消息的时间。标题 OCR 即使晚几秒完成，也不会推迟起点；重复滚轮和键盘输入会去重。网页端使用检测到视频身份切换的时间。未取得作者／标题的完整区间仍计入总平均时长，并归入「未分类」。

比如程序启动时正在播放 A：105 秒切到 B，115 秒切到 C，则只保存 B 的 10 秒；之后退出时不保存 A、C。只要工具保持运行，视频暂停、缓冲等处于两次切换之间的时间也属于该区间。暂停工具或更换绑定窗口会放弃未完成区间，恢复后从下一次切换重新建立完整起点。

自动跳过也按切换起点计算经过时间，无需读取进度。桌面约每 150 毫秒检查到期，视频信息解析失败时仍能统计区间，但只有可匹配有效历史的视频才会按历史时长跳过。


观看记录持续保存，不受最近操作日志 300 条上限影响，重启后仍可统计和预测。旧版按播放进度保存、没有明确结束边界的记录保留在库中，但不参与新版统计和预测；无法补算其真实切换间隔。后续字幕不会在同一视频内反复进行整窗识别。


## 快速划走学习

监听绑定抖音窗口中的鼠标滚轮向下、键盘下方向键，以及鼠标左键纵向拖动。滚轮 700 毫秒内的连发合并成一次操作，不同输入设备在同一短时间内的尾随事件也会合并，合并事件不会重置观看计时；按住方向键只记一次。拖动纵向位移至少 40 像素且大于横向位移的 1.5 倍。小于去重间隔的极快连续切换可能合并，优先避免把长时间观看误计为短观看。

以 Windows 记录的原始输入事件时间计算间隔，不使用 Python 回调排队后开始执行的时间；按毫秒精度比较边界。首次动作只记时间，暂停／恢复、重新开启监听或重新绑定后重新计时。以阈值 4 秒为例：3 秒进入解析，4 秒和 6 秒均不解析、不入库。此规则按用户的“可能切换动作”判断，不等待 OCR 或播放进度确认；评论区内符合条件的动作仍可能被记入，可通过撤销纠正。

仅开启监听时只维持窗口画面缓存，**不周期性进行 OCR、可访问性文字读取或云端分析**。事件入队、后台任务开始、写入黑名单之前都会校验间隔。若排队期间调低阈值，不再符合条件的任务取消；调高阈值也不会把原先不合格的事件补算为合格。用户主动点击手动拉黑时，才另行进行一次按需读取。开启自动后在切换时识别当前视频，取得作者后停止本视频的 OCR；同时开启监听时，学习仍只由用户的合格切换动作触发，工具自动跳过只重置下一条视频的计时起点。

符合条件时立即冻结捕获流中划走前最近的一帧，拖动使用鼠标按下时的快照。快照只保存在内存；解析队列只读取这张图，不再读取已经变成下一条的窗口。解析完成后，浮窗显示 `@作者 视频标题 视频被加入黑名单（切换间隔 3.000 秒）`，保留 8 秒，间隔保留毫秒精度，历史记录同时保存触发时阈值。即使此时已经看到下一条、暂停或切换窗口，仍符合阈值的旧快照可以完成入库；提示中的标题与间隔对应被划走的视频。

该路径使用本地 OCR，不调用付费 AI。通过识别到的作者和完整标题建立视频匹配规则，并供自动模式匹配；不会因此拉黑整个作者。识别不到作者／标题时会明确提示，避免伪造信息。标题 OCR 不一致可能导致漏匹配，同名作者及相同标题可能发生碰撞，可删除或撤销规则。队列最多保留 8 张快照，繁忙或无法取得划走前新画面时会提示本次未入库；退出程序会结束尚未完成的解析。

## Chrome 连接

1. 在 Chrome 打开 `chrome://extensions`，开启开发者模式。
2. 选择「加载已解压的扩展程序」，选择发布目录的 `extension` 文件夹。
3. 复制扩展卡片的 32 位 ID，粘贴到桌面「设置 → Chrome 连接」，点击「注册本机连接」。注册只写当前用户的 Chrome Native Messaging 配置，无需管理员权限。
4. 打开或刷新抖音推荐页。若首页进入精选列表，点击左侧「推荐」。
5. 只有当前 Chrome 窗口中正在显示的目标标签页参与操作；切换标签或软件后暂停。

扩展只申请抖音网站访问、当前标签页访问和本地程序连接权限。当前版本不请求云端分析截图。网页更新可能需要重新适配。

更新、重新加载或重新安装扩展后，也需刷新已打开的抖音页面，让新内容脚本生效。若出现 `Extension context invalidated`，先刷新抖音页面，再清除扩展错误页中的旧记录。0.1.13 起，失效脚本会停止定时发送、清理事件监听并忽略迟到的切换指令；暂时找不到连接接收方时继续重试。若重新安装后扩展 ID 改变，请用新 ID 再次注册本机连接。

## 客户端自动定位与限制

程序通过 Windows 枚举抖音窗口，无需抖音位于前台。只有一个候选窗口时自动绑定；多个候选窗口时，可点击浮窗「绑定窗口」，再点击希望使用的抖音窗口，工具会取得并记住 HWND、所属进程及进程启动时间。绑定状态显示在浮窗，悬停可查看句柄。

绑定后即使其他软件成为前台，或抖音被其他窗口遮挡，仍按 HWND 读取抖音自己的画面：Windows 10 使用 PrintWindow，支持关闭系统边框的较新系统使用 Windows Graphics Capture。内容分析使用整个绑定窗口扣除当前播放器类型的排除区域，不再查找或确认窗口内部的视频矩形。窗口移动、缩放不需要重新绑定。解析得到的文字和链接只在本机用于匹配，截图不长期保存。

切换命令通过窗口消息定向发送到绑定窗口的渲染控件，不激活抖音、不向前台软件发送全局按键。若没有观察到实际切换，工具停止自动操作并提示。窗口最小化、隐藏或停止提供新帧时暂停识别，恢复画面后继续；关闭窗口后清除失效绑定并重新查找，重启软件时重新枚举，不沿用上次运行的裸句柄。

「自动识别」入口优先保持已绑定的抖音客户端，切到 Chrome 不会改绑。希望使用网页版时，在设置中选择「Chrome 网页版」。浮窗菜单的「重新自动查找窗口」可解除当前绑定并重新枚举。

不同客户端版本可能不提供视频或作者唯一标识；手动输入的作者规则按名称匹配，已有可靠账号 ID 的作者规则仍优先按 ID 匹配。快速划走的视频规则仍使用作者和完整标题匹配，不扩大为作者规则。缺少播放时间时不会猜测播放结束。本机抖音 8.7.0 已验证具体作者规则命中和定向滚轮切换，仍需更多实际视频验证。

## 数据

数据目录为 `%LOCALAPPDATA%\AutoSkip`，开发检查可通过 `AUTOSKIP_DATA_DIR` 指定隔离目录。黑名单、观看记录和最近 300 条操作保存在 SQLite 中；历史 API Key 和本地通信密钥用 Windows DPAPI 按当前用户加密。截图只在内存中临时分析，不保存完整视频或声音。当前规则匹配不发送数据到云端。

只需备份或迁移观看记录时，可在「观看统计」中导出 JSON；该文件仅包含观看记录，黑名单和设置需通过整个数据目录备份。退出后可备份整个数据目录；加密的 Key 不适合跨 Windows 账号迁移。若移动发布程序目录，需要再次注册 Chrome 本机连接。

仓库忽略虚拟环境、构建产物、`.local` 检查数据、`.env`、加密凭据和本地数据库；真实密钥、观看记录及个人截图应保留在本机数据目录中。

## 开发与检查

在 Windows 上使用 Python 3.12 x64；扩展语法和集成测试另需 Node.js，集成测试还需本机 Chrome 和 Playwright。发布目录中的 `AutoSkip.exe` 无需另装 Python。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt pyinstaller==6.19.0
.\.venv\Scripts\python.exe main.py
```

自动检查：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests/check_ui.py
.\.venv\Scripts\python.exe tests/check_overlay_controls.py
.\.venv\Scripts\python.exe tests/check_reparse.py
.\.venv\Scripts\python.exe tests/check_statistics_ui.py
.\.venv\Scripts\python.exe tests/check_switch_timing.py
node --check extension/content.js
node --check extension/worker.js
node --check extension/popup.js
```

扩展测试使用 Playwright 和隔离的无界面 Chrome，页面内容是本地构造的模拟抖音播放器，不登录任何账号。测试默认查找 `C:\Program Files\Google\Chrome\Application\chrome.exe`；其他安装位置可通过 `CHROME_PATH` 指定：

```powershell
npm install --prefix .local/extension-tests --no-save --package-lock=false playwright
$env:PLAYWRIGHT_MODULE = (Resolve-Path '.\.local\extension-tests\node_modules\playwright').Path
# 已安装 Playwright 时，直接将 PLAYWRIGHT_MODULE 指向其安装路径即可。
node --test tests/extension.test.cjs tests/extension_lifecycle.test.cjs
```

截至 2026-10-04，129 项 Python 单元测试及上述 5 项界面／切换计时检查通过，3 个扩展脚本的语法检查通过。界面与计时检查使用隔离数据和模拟内容。`tests/check_*live.py` 等实机脚本会读取或操作真实客户端，应按 [VALIDATION.md](VALIDATION.md) 的验证范围单独运行。

构建：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

产物为 `dist\AutoSkip`，包含 `AutoSkip.exe`、`bridge\AutoSkipBridge.exe`、运行依赖、`extension`、README、验证记录及第三方说明。必须保留整个发布目录。脚本只对本次 PowerShell 进程指定执行策略，不修改系统配置。

自动测试覆盖规则或／与组合、旧数据迁移、输入边界、OCR 排除区域、观看统计和模拟 DOM 行为，不能替代客户端及真实 Chrome 扩展的完整实机验收。
